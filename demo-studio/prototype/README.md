# DemoStudio 交互原型 · 评审说明

> **目的**：在写任何产品代码之前，把「导入项目 → 还原场景 → 录制操作 → 编排 → 出片」的**交互逻辑**定下来，供评审。
> **打开方式**：双击 `index.html`。单文件、零依赖、无需服务器。

---

## 怎么用（30 秒上手）

点右上角 **▶ 走完整流程**，它会自动跑一遍全部 5 步，并在第 4 步开始播放。

想自己操作，就按顶部 5 个步骤一步步点，或者直接跳到任意一步。

---

## 五个步骤分别在验证什么

| 步骤 | 你要看的是 | 关键交互 |
|---|---|---|
| **1 导入项目** | 导入不是"选个文件夹就完事"，而是一次**可诊断的探测**：识别框架 → 判断启动命令 → 起 dev server → 健康检查 → 枚举路由 | 每一步都有耗时和成功/失败状态，失败时能看到卡在哪 |
| **2 还原场景** | 把"AI 还原界面"拆成**可解释的确定性加固清单**：冻结时间、录制网络、暂停 CSS 动画、本地化字体 | 明确写出「未命中的请求会直接报错，绝不静默走真实网络」 |
| **3 录制操作** | **零门槛路径 + 录制专注模式**：点 `● 录制` 后进入专注模式——左右面板、步骤条、工具条、传输条全部隐藏，舞台占满窗口，底部只留一条折叠的事件带 | 录制中鼠标经过锚点会高亮；停止后事件自动转成时间线动作 |
| **4 编排** | 右侧是 **AI 对话面板**，不是参数面板。点画面里的元素 → 它被**引用进输入框** → 说一句话让 AI 去改 | 时间线片段可拖可点；规则问题直接进对话流并带「帮我修」 |
| **5 出片** | 存在规则错误时**禁止导出**；渲染完成后展示确定性校验结果 | 「两次渲染逐帧一致 ✓」——这是整个架构的地基 |

## 录制专注模式（点 `● 录制` 后自动进入）

录制时你只需要看画面，其他 UI 一律让位：

```
┌──────────────────────────────────────────────────────────────┐
│ ● REC 00:05.0   已记录 2 个动作      [展开时间轴 ⌃] [■ 停止录制] │  ← 只剩时间码/计数/停止
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                     场景（占满整个窗口）                        │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 0s        2s        4s        6s        8s        10s        │  ← 折叠时间轴：
│ ▬▬▬ server-card ▬▬▬      ▬▬▬ ssh-btn ▬▬▬                     │    一条事件带 + 播放头
└──────────────────────────────────────────────────────────────┘
```

隐藏清单：左栏「场景与锚点」、右栏「检查/属性/事件」、步骤条、品牌区、舞台工具条、播放传输条、时间线表头与轨道标签。

保留清单：**场景**、**REC 状态与动作计数**、**■ 停止录制**、**折叠时间轴**（一条事件带，能看到已录内容）。

两个细节：

- **画面尺寸**：舞台从 1174×660 放大到 **1614×908**（约 +90% 面积）。更关键的是相机基准缩放从 `0.78×` 提到 **`1.20×`** —— 1440×900 的窗口在这个缩放下几乎铺满 1920×1080 画布，看得全也看得清。录制时要能点到每一个控件，这比"浮动小窗"式的构图重要得多。
- **提示自动让位**：录制提示只在第一次点击前显示；一旦记下第一个动作就消失，把画面完全交给你。
- **「展开时间轴」**：录制中想回看已录内容，点它可临时展开成完整 4 轨视图，再点收起。

## AI 对话面板：不说参数，说话

面向不懂剪辑的用户，右侧的**属性 / 检查 / 事件三个面板已经全部删除**，换成一个对话。

### 核心动作只有两步

```
① 点元素  →  ② 说一句话
```

**点哪里都能引用**：

| 点击位置 | 引用成 |
|---|---|
| 舞台画面里的控件 | `@ai-send`（锚点 id） |
| 左栏「场景与锚点」列表 | 同上 |
| 时间线上的动作片段 | `@动作3·server-card` |
| 时间线上的字幕片段 | `@字幕2·选中目标服务器` |
| 时间线上的相机关键帧 | `@相机5` |

引用会变成输入框上方的 **chip**（可单独 × 掉），然后打字发送。
**快捷指令会跟着引用对象变**：引用锚点时给「演示我点击它 / 给它配一条字幕 / 放大这里 / 这一步太急了，放慢」，引用字幕时给「再短一点 / 删掉这条」。

### 「帮我修」不是装饰，是真的会改

规则检查的结果不再进独立面板，而是**一条条走进对话流**：

```
AI 导演
┌────────────────────────────────┐
│ 提醒一下 · 第 250 帧              │
│ 第 250 帧点击时，相机在 7 帧前刚移动过 │
│ 建议相机停稳 ≥8 帧再出指针           │
│ [帮我修]  [先不管]                │
└────────────────────────────────┘
```

点「帮我修」会**真的把那个相机关键帧往前挪**，然后回一句「已把推进动作提前到第 242 帧」。
问题修好后，那条提醒会**自动从对话里消失**（不会留一堆过期的红字）。

### AI 实际能改的东西（都是真的改时间线，不是演的）

| 你说 | 它做 |
|---|---|
| 演示我点击它 | 在时间线插入点击动作 + 指针轨迹 |
| 给它配一条字幕 | 插入字幕（自动避开 16 帧间隔规则） |
| 放大这里 | 在当前帧插入推近关键帧并保持 30 帧 |
| 帮我整体配运镜和字幕 | 重排整个相机轨道 + 指针轨迹 + 字幕 |
| 检查一下有什么问题 | 汇报规则检查结果 |
| 这个动作慢一点 / 删掉 | 调整或删除引用到的片段 |
| 这条字幕再短一点 | 截短引用的字幕文本 |

### 录制结束自动交棒

录制停止后，AI 主动接上：

```
录制完成：记下了 2 个动作（2 个事件）。
要我一键配上运镜和字幕吗？也可以继续在画面里点元素，告诉我要改哪里。
[一键配运镜和字幕]  [先自己看看]
```

用户不需要知道「下一步该去哪个面板」。

### 一个真实的坑（值得写进架构文档）

第一版做完，聊天消息**每条都塌成 17px 高、气泡浮在面板外面**。原因：

舞台里那套模拟的 AIShell 界面已经有 `.bubble{position:absolute}`（AI 气泡样式），
而聊天面板的消息气泡也叫 `.bubble` —— 两条规则撞名，后者的 `position:absolute` 生效，气泡脱离文档流。

修法是把聊天面板的类名前缀化（`.cbub`）。**这正是 `incentive-promo/real-ui.css` 用 `.rui` 前缀解决过的同一类问题**，只不过这次踩在了自己身上。

> 结论：一旦产品要加载「用户的真实界面」，**所有自有 UI 的类名都必须带命名空间前缀**，否则迟早撞车。这条应该进架构文档的硬约束。

## 三个刻意做进去的设计决策

### 1. 状态由「操作重放」推导，不是外部注入

`deriveAppState(frame)` 会把 `0..frame` 的动作重放一遍，得到界面状态——界面里打开哪个面板、输入框里有什么字、弹窗开没开，全是帧号的纯函数。

这验证了架构文档的 **ADR-003**：不要求用户应用提供 `setState` API，因此能适配任意前端项目，且天然满足"每帧从 0 重放"的确定性要求。

👉 拖动时间轴来回擦，界面状态会跟着正确回放，不会错乱。

### 2. 指针永远绑定锚点，不用绝对坐标

舞台左侧列出 9 个锚点，每个都有 id 和矩形。指针、点击涟漪、高亮环全部由锚点中心算出，相机缩放时自动跟随。

👉 打开「锚点热区」开关，鼠标在画面上移动会看到热区高亮和 id 标签。
👉 这个原型里 DOM 也按锚点表同一组坐标绝对定位——所以指针**必然**落准，不可能偏。

### 3. 返工教训变成了自动规则

`lint()` 里 7 条规则，全部来自你现有 `video/` 项目的真实教训：

| 规则 | 出处 |
|---|---|
| 字幕间隔必须 ≥ 16 帧 | `Video.tsx` 注释「间隔 ≥16 帧避免进出场叠影」 |
| 相机停稳 ≥ 8 帧再出指针 | 分镜文档「节奏原则」 |
| 动作间隔 < 12 帧 → 节奏过快 | 观看体验 |
| 锚点不存在 → 禁用导出 | `anchors.tsx` 的「失败要响亮」哲学 |
| 尾部留白 < 45 帧 → 结尾仓促 | — |

👉 **动手试一下**：在第 4 步把某条字幕往左拖，让两条字幕挨近，「检查」立刻报错，而且「导出成片」会被禁用。
👉 「✦ AI 一键展开」生成的编排默认**不触发任何告警**——规则集是自洽的。

## 请你重点评审的问题

1. **「点元素 + 说话」够不够？** 我在"完全对话"和"完全参数面板"之间选了对话优先。你实际操作下来，哪些事还是希望**直接拖**而不是说？（现在时间线片段可以拖，其余都要说）
2. **AI 理解不了怎么办？** 原型里 AI 是规则驱动的：听懂「放大这里」，听不懂「让它更高级一点」。真实产品要接 LLM，那**说错了怎么撤销**？——目前原型**没有撤销**，而 AI 一旦能改时间线，撤销就是必需品。这是我看到的最大缺口。
3. **引用会不会过期？** `@动作3` 是按索引存的，AI 增删片段后索引会变。真实产品需要**稳定的片段 ID**，还要处理"你引用的东西已经被删了"。
4. **录制的定位。** 我把它做成主推路径（零门槛起手）。它该只是"起手式"（录完进对话精修），还是也要能直接出片？
5. **规则的分寸。** 现在 error 阻断导出、warn 只提醒。哪些该更严（比如字幕遮挡关键信息也阻断）？哪些其实可以放宽？
6. **时间线粒度。** 现在是 4 条轨道。够用吗？高亮 / 标注 / 键盘浮层要不要独立成轨？
7. **出片之后。** 原型停在渲染完成。要不要内置「抽帧审片 + 逐帧批注」？这是你现有流程最痛的一环。

## 这个原型**没有**做的（别误判）

- 没有真实渲染，渲染进度是模拟的
- 没有真实采集，锚点表是写死的 9 个
- **没有真实 LLM**：AI 是规则驱动的，只认 README 里列出的那些说法
- **没有撤销 / 重做**（见问题 2，这是当前最大的缺口）
- 引用按索引存，AI 增删片段后可能指错（见问题 3）
- 只有一个场景（AIShell 工作台），没有多场景切换与转场
- 不可保存/加载项目文件

这些都属于 M0–M2 的实现范围，见 `../docs/ARCHITECTURE.md`。

## 验证记录

已在无头 Chromium（1728×1050）实跑通过：

- 完整流程：导入 → 采集 → AI 编排 → 播放，无控制台报错
- 录制路径：`● 录制` → 进入专注模式 → 画面内点击 ×2 → `■ 停止录制`，事件正确转为动作（2 事件 / 2 动作），并弹出 AI 交棒消息
- 录制专注模式：`body` 类为 `recording tl-compact`，舞台 1174×660 → **1614×908**；退出后布局完整还原
- 折叠时间轴：「展开时间轴」→ 216px，「折叠」→ 76px，两种模式都正确渲染
- 对话面板：点画面元素 → `@ai-send` 引用进输入框；重复点击同一元素不重复引用
- AI 指令实测：「演示我点击它」→ 动作 5→6（第 440 帧）；「给它配一条字幕」→ 字幕 4→5；「放大这里」→ 相机 13→15；全程 **lint 0 错误 0 警告**
- AI 按钮实测：「一键配运镜和字幕」→ 生成 7 相机关键帧 / 4 指针关键帧 / 1 字幕，且过期的「没有字幕」提醒自动从对话中消失
- 出片路径：无错误时可导出，完成后显示 timeline hash 与「两次渲染逐帧一致 ✓」
- 时间线无溢出滚动条、弹窗在任意窗口尺寸下不被裁切
